# StoreAMO 0.4.3.83 — migración de firma

## Estado observado

StoreAMO 0.4.3.82 (`com.desarrollamo.storeamo`) fue publicado con certificado SHA-256:

`48F3671ED5F30D065EE4BAAC5CB509C4B59D3FF116D21E6CA81B21029862AB51`

El backup de su keystore sigue publicado cifrado como `StoreAMO-signing-recovery-v1.cms`, pero la clave privada externa que debía descifrarlo no está disponible en GitHub, GitHub Actions Secrets ni en el Termux inspeccionado. Los cuatro secrets de release existentes tampoco contienen un keystore Base64 válido.

## Identidad preservada disponible

En Termux existe una identidad privada completa y verificable en `~/.storeamo-signing/`, con certificado SHA-256:

`7BD60FD751723041CF2802BEA01FBD83700410A1FD2DD019CACBCD739CB72DCF`

La migración 0.4.3.83 adopta explícitamente esa identidad como la firma permanente para StoreAMO a partir de esta versión.

## Consecuencia Android

Android no permite reemplazar una app instalada por otra APK con el mismo package ID y una firma distinta. Por eso 0.4.3.82 no puede actualizarse en sitio a 0.4.3.83.

La migración requiere una única desinstalación de StoreAMO 0.4.3.82 y reinstalación de 0.4.3.83. `StoreAMO Install` es un paquete separado y debe conservarse durante ese paso para poder reinstalar la Store estable.

A partir de 0.4.3.83, toda release debe exigir la firma `7BD60FD751723041CF2802BEA01FBD83700410A1FD2DD019CACBCD739CB72DCF`.

## Cambio funcional 0.4.3.83

La tienda descarga los APK directamente, verifica SHA-256 y los entrega al instalador visible de Android. Ya no abre GitHub como paso normal de instalación de aplicaciones del catálogo.

## Invariantes

- No generar ni rotar otra clave si la identidad 7BD60F… está disponible.
- No declarar que 0.4.3.83 es una actualización en sitio de 0.4.3.82.
- No borrar `StoreAMO Install` durante la migración.
- No publicar una release si el fingerprint firmado no coincide exactamente con 7BD60F….
- Mantener el backup privado `~/.storeamo-signing/` fuera del repositorio público.
